# Release v0.2.0 — Document Intelligence Pipeline

**Phase**: 2 of 7 (see project roadmap)
**Status**: Complete

## What's included

- **PDF text extraction** (FR1): full text extracted from RFPs and
  technical manuals via `pdfplumber`, normalized (whitespace collapsed,
  control characters stripped).
- **Excel structured extraction** (FR2): requirement matrices parsed
  back into structured records via `pandas`, preserving the original
  column shape from Feature 0001.
- **Idempotent ingestion** (FR6/NFR1): a database-level uniqueness
  constraint on `ingested_content.source_checksum` — not just an
  application-level check — guarantees re-running the pipeline never
  creates duplicate records, even under concurrent or retried runs.
- **Per-document fault isolation** (FR8/NFR5): one corrupt or missing
  file is recorded as a `status='failed'` row with its error message,
  without aborting the rest of the batch.
- **Apache Airflow orchestration**: a custom Airflow image (extending
  `apache/airflow:2.9.3`) runs the real pipeline via the
  `ingest_documents` DAG — the same `run_ingestion` function used by
  the CLI and the unit tests, with no duplicated logic.
- **Independent uv project** (`backend/ingestion_pipeline/`): isolated
  dependencies from the document-generator project (see ADR-0003).

## Architecture highlights

- Strategy/Factory pattern for parsers, mirroring the generator design
  from Feature 0001 — the same extensibility pattern reused
  consistently across the codebase.
- Repository pattern separating a **read-only** view of
  `document_metadata` (owned by document-generator) from a
  read/write `ingested_content` repository (owned by this pipeline).

## Real-world debugging during this release

Three environment/infrastructure bugs were found and fixed by running
the full system end-to-end, not caught by unit tests alone:

1. **uv workspace auto-discovery** silently shared a single virtual
   environment between two independent projects, uninstalling
   dependencies out from under the generator project.
2. **Relative file paths** stored in the database broke the moment a
   different process, running from a different working directory,
   tried to read them — fixed by storing absolute paths at write time.
3. **Airflow custom-image dependency conflicts**: installing extra
   packages without Airflow's official constraints file silently
   upgraded SQLAlchemy past what Airflow 2.9.3 supports, breaking the
   scheduler; the constraints file then exposed a second issue —
   SQLAlchemy's 2.0-only `DeclarativeBase` class had to be replaced
   with the backward-compatible `declarative_base()` function.

Full details: see the Implementation Notes section of
[Feature 0002](https://github.com/funk1090/ai-solution-architect-portfolio/blob/main/docs/architecture/features/0002-document-intelligence-pipeline.md).

## Test coverage
