# Release v0.8.0 — Web Frontend

**Feature**: 0008 (post-roadmap extension)

## What's included

- **Streamlit web frontend** (`frontend/`, seventh independent uv project): Corpus, Pipeline, Ask and Classify pages. A pure client of the API: no business logic, a single typed `ApiClient`, and the API key stays on the Streamlit server (never sent to the browser).
- **API v0.8.0**:
  - `GET /corpus/summary`: generated / ingested / indexed counts per document type.
  - `POST /assistant/ask` now also returns `source_details` (document type and file name per source). `sources` is unchanged, so existing clients keep working.
  - The embedding model is loaded once per process instead of on every request.
- **CI**: seventh job (`frontend`). Tests: 12 in `backend/api`, 16 in `frontend`.

## Validated against the real stack

- `/corpus/summary` returned real counts (240 generated, 240 ingested); 422 without a key, 401 with a wrong one.
- `/assistant/ask` returned the grounded answer with sources shown as `rfp - rfp_0000.pdf` instead of raw checksums.
- All four pages exercised in the browser against the live API.
- Embedding model loaded once: confirmed in the server log (v0.7.0 reloaded it before every request). Warm-call latency 4.5 s -> 1.9 s (indicative, n=1).

## Bugs caught before shipping

- Unauthenticated requests could reach the database through a FastAPI dependency; caught by a unit test and fixed.
- A flaky page test (3 s default timeout) fixed before it could fail CI.

## Honest findings

- A short requirement ("... encrypt all data using AES-256.") is classified as *Compliance*, the longer Phase 3 sentence as *Security*: expected with ~83% accuracy on synthetic data; documented in the UI.
- Compliance validation (RFP requirements vs. technical manuals) is deliberately **not** included: it is new business logic and the synthetic manuals lack category-aware content. Planned as Feature 0009.
