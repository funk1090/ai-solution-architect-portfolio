# Release v0.7.0 — Product Hardening (Roadmap Complete)

**Phase**: 7 of 7 (see project roadmap)
**Status**: Complete — this closes the original 7-phase roadmap.

## What's included

- **Unified API** (FR1): `backend/api/`, a sixth independent uv
  project, exposes document generation, ingestion, classification, and
  the RAG assistant behind a single FastAPI service — reusing every
  module's existing, already-tested code directly.
- **API key authentication** (FR2) on every route except `/health`.
- **Prometheus metrics** (FR3) at `/metrics`, via
  `prometheus-fastapi-instrumentator`.
- **CI** (FR4): `.github/workflows/ci.yml`, one job per module —
  **all 6 jobs pass** on GitHub Actions.
- **`docs/architecture/SYSTEM_OVERVIEW.md`** (FR5): a single
  consolidated document tying all seven phases together for a
  first-time reader.

## Validated end-to-end over real HTTP

- `GET /health` → 200, no auth required.
- Missing API key → 422.
- `POST /classifier/classify` → 200, real prediction from the Phase 6
  model.
- `GET /metrics` → 200, valid Prometheus exposition format.
- `POST /assistant/ask` → 200, a fully grounded answer citing 4 real
  source documents with real budget figures — the same quality
  validated by CLI in Phase 4, now behind authenticated HTTP.
- **CI**: all 6 jobs (`document-generator`, `shared-core`,
  `ingestion-pipeline`, `requirement-classifier`, `knowledge-assistant`,
  `api`) green on push.

## A bug caught before it shipped

`document_generator` and `requirement_classifier` default to relative
paths (`./datasets/generated`, `./models`), which would have resolved
against `backend/api/`'s own working directory — a different location
than every other module uses. Fixed proactively via explicit
environment variables in the API's `.env`, the same lesson as Feature
0002's absolute-path fix, this time anticipated rather than discovered
by a failure.

## An honest scope boundary

CI runs only the unit test suites already proven to need no live
infrastructure. The real end-to-end validations — Airflow's DAG,
Ollama inference, parallel ingestion against Postgres — were done
manually in Features 0002, 0004, and 0005, and are not re-run in CI.
Automating those would mean standing up Postgres+pgvector, Airflow, and
Ollama inside CI for marginal additional confidence — documented as a
deliberate trade-off, not a gap nobody noticed.
