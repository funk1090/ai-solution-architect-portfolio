# Release v0.9.0 — Compliance Validation and Containerized Deployment

**Features**: 0009 and 0010 (post-roadmap extensions)

## What's included

- **Compliance validation (0009).** For each RFP requirement, retrieve evidence from the technical manuals and judge it with a local LLM. Verdicts: `SUPPORTED`, `PARTIAL`, `NOT_EVIDENCED`, `NEEDS_REVIEW`. Groundedness first: no passage above the threshold means `NOT_EVIDENCED` without calling the LLM. Available as CLI (`compliance-check`, `compliance-evaluate`), API (`GET /compliance/rfps`, `POST /compliance/check`) and a **Compliance** page in the frontend that shows the full supporting passages.
- **Ground truth (ADR-0008).** A capability catalog in `shared_core` defines what the product supports; technical manuals are generated from it, so the correct answer for each requirement is known and the engine can be measured.
- **Containerized deployment (0010).** Dockerfiles for the API and the frontend, and a compose file where `docker compose up` starts PostgreSQL, API and frontend. Optional profiles: `ollama` (GPU) and `airflow`. Secrets come from the environment; `API_KEY` has no default. Containers run as non-root with healthchecks; ports are bound to `127.0.0.1`.
- **API rate limiting (0010).** Token bucket per API key, two tiers (default 120/min; 10/min for routes that call the LLM or heavy pipelines). `429` with `Retry-After`, a Prometheus counter `api_rate_limited_total{tier}`, and a friendly message in the frontend.
- **CI**: eighth job (`docker`) that builds both images, starts the stack and runs `scripts/smoke.sh` (health, authentication, rate limiting).
- **Docs**: final architecture diagram (`docs/diagrams/`), updated system overview with a Future work section.
- Tests: 33 in `backend/api`, 31 in `knowledge_assistant`, 22 in `frontend`.

## Measured results

Synthetic data: 100 RFPs, 110 technical manuals. Labels come from the capability catalog.

| Strategy | Accuracy | F1 |
|---|---|---|
| Baseline "always SUPPORTED" | 0.540 | 0.701 |
| Retrieval only, threshold 0.30 (full set) | 0.728 | 0.799 |
| Retrieval only (sample of 200) | 0.755 | 0.821 |
| Retrieval + LLM judge, temperature 0 (sample of 200) | 0.890 | 0.911 |

Retrieval alone is limited by precision (0.665 at the best threshold); recall is 1.000 at 0.30. The judge adds about 13 accuracy points on the same sample.

Images: API 3.99 GB, frontend 1.28 GB.

## Validated against the real stack

- Compliance run through the CLI, the API and the browser (inside the containers) gives the same verdicts for the same RFP; two consecutive runs are identical.
- Rate limiting over real HTTP: `200 200 200 429 429` with a limit of 3 per minute.
- `docker compose up -d --build --wait`: PostgreSQL, API and frontend healthy; `scripts/smoke.sh`: 5/5 checks pass.
- The API container reaches the existing GPU Ollama through `host.docker.internal`.

## Bugs caught before shipping

- **Stale duplicate RFP rows**: regenerating the RFPs left 10 old rows next to the new ones (ingestion deduplicates by checksum, not by path). Found because `compliance-check` refused to guess between two matches; it would also have skewed the evaluation.
- **Non-deterministic judge**: the same requirement gave PARTIAL in the CLI and NOT_EVIDENCED in the UI because no temperature was set. Fixed (temperature 0, fixed seed); earlier measurements were discarded and redone.
- **Fresh-database failure, caught by the new CI job**: `/corpus/summary` only tolerated a missing `document_chunks` table, so on an empty database (a fresh clone, or CI) it returned 500. It never showed locally because the tables already existed. The `docker` job failed, the endpoint was fixed (a missing table counts as empty) and covered with tests; all 8 CI jobs are green.
- **Evidence preview hid the proof**: the UI cut each passage to 300 characters, showing the start of the manual instead of the sentence the judge cited. It now shows the full passage.

## Honest findings

- The judge still marks one out-of-catalog requirement ("standardized data exchange formats") as `PARTIAL`, citing passages that do not mention it. The UI makes the error visible instead of hiding it.
- Numbers are optimistic: synthetic data with shared vocabulary, and the similarity threshold was selected on the same data used to evaluate it.
- With a single shared API key, the rate limit is effectively global; it protects the GPU, not individual users. It does not throttle brute-force attempts with wrong keys.
- Plain `docker compose up` no longer starts Airflow or the containerized Ollama; they moved to profiles.
- The write path inside the containers (generate, ingest, index on an empty database) was not exercised: the existing database holds documents with host paths, and re-ingesting them from a container would fail.
