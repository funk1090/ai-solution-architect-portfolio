# Release v0.4.0 — Enterprise AI Knowledge Assistant

**Phase**: 4 of 7 (see project roadmap)
**Status**: Complete

## What's included

- **Text chunking** (FR1): fixed-size, overlapping word-based chunks of
  RFP and technical manual text.
- **Local embeddings** (FR2): `sentence-transformers`
  (`all-MiniLM-L6-v2`), no external API calls.
- **Vector storage** (FR3): `pgvector` on the existing PostgreSQL
  instance — no new database service to operate.
- **Idempotent indexing** (FR7): a database-level uniqueness constraint
  on `(source_checksum, chunk_index)` prevents duplicate chunks on
  re-runs.
- **Grounded answer generation** (FR5/FR6): a local Ollama model
  answers questions using only retrieved context, always citing its
  sources.
- **Anti-hallucination guarantee** (FR9/NFR5): if nothing clears the
  similarity threshold, the LLM is never called — a fallback response
  is generated by application code instead.
- **Fourth application of the Strategy/Factory pattern**
  (`EmbeddingModelFactory`, `LLMBackendFactory`), keeping both the
  embedding model and the LLM backend swappable.

## Real, GPU-accelerated results

Validated against 20 real generated RFPs, live PostgreSQL with
`pgvector`, and a GPU-accelerated Ollama instance (confirmed via
`nvidia-smi` showing active utilization during inference):

- **Grounded, multi-source answer**: "What is the budget range
  mentioned in the proposals?" correctly retrieved four chunks from
  four different documents and synthesized an answer citing real
  figures from each — including an honest note where a figure wasn't
  present in one source, rather than fabricating it.
- **Correct fallback, twice over**: an out-of-domain question and a
  domain-relevant-but-genuinely-unindexed one (see below) both
  triggered the grounded fallback response instead of a hallucinated
  answer.

## An instructive non-bug

Asking about security requirements returned the "insufficient grounded
information" fallback — not because of a defect, but because the
generated RFP body text uses generic Faker vocabulary with no real
security-related content (unlike the Excel generator, which got
category-aware vocabulary in
[ADR-0004](https://github.com/funk1090/ai-solution-architect-portfolio/blob/main/docs/architecture/adr/0004-correlated-synthetic-labels.md)).
The system correctly recognized it had nothing relevant to ground an
answer in. Extending that same category-aware vocabulary to RFP/manual
text — or indexing the already-correlated Excel data directly — is
tracked as the natural next improvement.

## Infrastructure changes

- `postgres`'s Docker image switched to `pgvector/pgvector:pg16` —
  existing data verified intact across the migration (row counts
  before/after matched). Applying the new image to an already-running
  container required an explicit `--force-recreate`; a plain
  `docker compose up -d` silently kept the old image running despite
  the compose file being updated.
- Reused an already-running, unrelated Ollama container instead of
  starting a conflicting second instance on the same host port — see
  [ADR-0007](https://github.com/funk1090/ai-solution-architect-portfolio/blob/main/docs/architecture/adr/0007-vector-store-and-llm-backend.md).

## Architecture highlights

- Fifth independent uv project in the monorepo
  (`backend/knowledge_assistant/`), the fourth consumer of the
  `shared_core` package (ADR-0006) — validating that investment's
  payoff for a second time.
- `document_chunks` deliberately kept local to this module rather than
  added to `shared_core`, per that ADR's own extraction principle: no
  other module needs it (yet).
- Vector storage is accessed exclusively through a
  `VectorStoreRepository` interface — switching to a dedicated vector
  database later means one new implementation, not a pipeline redesign
  (see ADR-0007's Portability section).
