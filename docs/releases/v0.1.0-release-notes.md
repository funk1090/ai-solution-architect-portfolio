# Release v0.1.0 — Synthetic Enterprise Document Generator

**Phase**: 1 of 7 (see project roadmap)
**Status**: Complete

## What's included

- **RFP Generator** (FR1): synthetic Request for Proposal documents in
  PDF, with fictional issuing company, project scope, budget range, and
  technical requirements.
- **Excel Requirements Generator** (FR2): technical requirement matrices
  in `.xlsx`, with requirement ID, description, category, priority, and
  source RFP reference.
- **Technical Manual Generator** (FR3): structured technical manuals in
  PDF, with introduction, specifications, procedures, and appendix
  sections.
- **Metadata persistence** (FR4): every generated document's metadata
  (type, path, SHA-256 checksum, timestamp, related entity, seed) is
  recorded in PostgreSQL via a repository abstraction.
- **Reproducibility** (FR5, NFR1): identical seeds produce identical
  output, validated by automated tests.
- **CLI** built with Typer, exposed as the `document-generator` command.

## Architecture highlights

- Strategy/Factory pattern for document generators — adding
  `ExcelRequirementsGenerator` and `TechnicalManualGenerator` after
  `RFPGenerator` required zero changes to `base.py`, `cli.py`, or
  `repository.py` (see ADR references below).
- Repository pattern isolating persistence — all 9 unit tests run
  without a live database connection, using
  `InMemoryDocumentMetadataRepository`.
- Filesystem + PostgreSQL-metadata storage strategy (ADR-0002),
  avoiding database bloat from binary content.

## Notable issue resolved during implementation

`fpdf2`'s `multi_cell()` did not reliably reset the horizontal cursor
position across consecutive calls in this environment, eventually
raising `FPDFException: Not enough horizontal space to render a single
character` — even for short, plain ASCII text with no unusual
characters. Diagnosed by reproducing the failure in an isolated minimal
script rather than guessing from the stack trace, which showed the
issue was structural (missing `pdf.ln()` between calls), not
content-related. Fixed by adding an explicit `pdf.ln()` after every
`multi_cell()` call across all PDF-producing generators.

## Test coverage

9 unit tests across 3 generators, covering:
- Correct file count generated
- Unique checksums per file (no duplicates within a run)
- Reproducibility with a fixed seed
